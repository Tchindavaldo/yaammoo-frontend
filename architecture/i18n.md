# Langues (i18n) — Français / English

## Principe

- Bibliothèque : **i18next** (JavaScript pur, publiable par OTA).
- **Les clés sont les textes français eux-mêmes** : `t("Ajouter au panier")`.
  - En français, la clé s'affiche telle quelle (ou sa surcharge de `fr.json`).
  - En anglais, sa traduction dans `en.json` ; clé absente → texte français.
- Variables : `{{a}}`, `{{b}}`… — `t("{{a}} plat{{b}}", { a: n, b: n > 1 ? "s" : "" })`.
  Une traduction peut ignorer une variable (`"{{a}} dish{{b}}"`, `"{{a}} unread"`).

## Fichiers

| Fichier | Rôle |
|---|---|
| `src/i18n/index.ts` | Init i18next (synchrone), `t()`, `getLanguage()`, `setLanguage()`, `dateLocale()`, `LANGUAGES` |
| `src/i18n/locales/en.json` | Traduction anglaise de chaque clé |
| `src/i18n/locales/fr.json` | Surcharges françaises (changer un mot sans toucher au code) |
| `src/features/profile/components/LanguageSheet.tsx` | Bottom sheet Settings → Langue (Français / English) |

## Langue active

1. Choix enregistré (`SecureStore` clé `app_language`, `localStorage` sur web) ;
2. sinon langue du téléphone : anglais si le téléphone est en anglais, sinon français.

Lecture **synchrone** (`SecureStore.getItem`) : `t()` est juste dès le premier
import, y compris dans les constantes de module. `setLanguage()` enregistre le
choix puis **recharge l'app** (`Updates.reloadAsync`) pour tout réappliquer.

Dates : `toLocaleDateString(dateLocale(), …)` (`fr-FR` / `en-GB`) ; `moment`
suit la langue (`moment.locale`). Les montants restent formatés `fr-FR`.

## Règles

- **Tout nouveau texte affiché** passe par `t("texte français")`.
- Dans un fichier qui a déjà une variable `t`, importer `{ t as tr }`.
- **Jamais** `t()` sur une valeur envoyée au backend ou comparée à une donnée
  backend (`"Aucun"`, `"Disponible"`, statuts, ids de type `"surplace"`).
- Comparer à un texte traduit : traduire les deux côtés
  (`user.creneau === t("Sur place")`).
- Modifier un mot : `fr.json` (français) ou `en.json` (anglais), puis OTA.

## Non traduit (volontairement)

Noms propres et marques (villes, Orange Money, MTN, WhatsApp, Netflix), données
de démo envoyées au backend (`Embalage`, boissons par défaut), messages du
backend / MobileWallet (affichés tels quels), logs et télémétrie.
